# Большие инженерные проекты: измеренные ограничения

Дата: 2026-09-28. Среда: macOS arm64, Apple M1, Bun 1.4.2.
Воспроизведение: `bun scripts/project-scale-benchmark.ts`.
Повторный локальный результат: начало 11:11:09 UTC, exit 0. Синтетический
набор не является моделью станции.

Путь проверки: действующий `device`/`signal`/`project`, BuildArtifact, decode,
Runtime и настоящий SQLite `:memory:`. Приёмка проекта не обходится. Три полных
пакета и три одиночных изменения на размер; события сериализуются без сети.
Source compiler, драйвер, физика, routing, браузер и запись на диск не измерялись.
Короткий прогон включает холодные эффекты и не устанавливает производственную ёмкость.

## Что уже мешает полному проекту

| Проверка | Результат |
| --- | --- |
| 64 устройства / 512 сигналов | Приняты; полный пакет, медиана 6,439 мс |
| 128 устройств / 1024 сигнала | Приняты; полный пакет, медиана 11,545 мс |
| 256 устройств / 2048 сигналов | Приняты; модель 663765 символов, пакет 20,977 мс |
| 1024 устройства / 8192 сигнала | Приняты; модель 2676022 символа, пакет 84,157 мс |
| 2048 устройств / 16384 сигнала | Проверка Project пройдена, BuildArtifact отклонён: модель 5417078 символов |
| 512 и 513 соединений между 10 устройствами | Оба проекта приняты |

Глобальные лимиты 128 устройств и 512 соединений удалены из Project validation.
Сохраняются структурные проверки, ограничения ёмкости портов и независимый
лимит BuildArtifact в 4 млн символов модели. На синтетических проектах до 1024
устройств измерены сборка артефакта, decode, Runtime и SQLite `:memory:`; это не
подтверждает производственную ёмкость, скорость исходной компиляции, физики или
дисковой БД.

Для диаграммы введён отдельный бюджет: когда связей больше 64, UI прокладывает
и показывает по 16 связей за страницу. В реальном browser-прогоне Builder и
Runtime приняли 130 устройств и 513 связей; переход показал именно `E16`–`E31`,
не удаляя остальные связи из модели. Мобильный прогон при viewport 390 px не
имел горизонтального переполнения. Это ограничивает число рассчитываемых
маршрутов, но не число отображаемых устройств: весь набор всё ещё рисуется на
сцене и при крупной модели становится мелким. Виртуализация SVG-оборудования и
проверка реальной сложной топологии остаются следующей задачей.

На последнем размере подтверждены 49155 строк в SQLite, ноль ошибок записи и

одного сигнала. Это измеренный объём сериализации, а не измеренная сетевая скорость.
Архив выполняет отдельные INSERT внутри транзакции; запись на диск и PostgreSQL
потребуют отдельной проверки.

## DX и следующие границы

- Сгенерированный через `Object.fromEntries` набор сигналов выявил конфликт
  индексной сигнатуры с `label/x/y` в `device()`. Это самостоятельная ошибка
  типизации DSL; в первой версии benchmark использованы восемь явных сигналов.
  **Исправлено в типах конструктора:** динамический набор теперь принимает
  обычные координаты и подпись. Неизвестные имена каналов остаются `unknown`
  до проверки через `equipmentSignal`/`equipmentSignals`; явно объявленные поля
  сохраняют точные типы и writable. Расчёт и runtime-валидация не изменены.
- Вычисленные ID и координаты в генераторах не дают однозначного диапазона
  исходника для drag-edit. Валидный проект ещё не означает редактируемый мышью
  отдельный сгенерированный экземпляр. Нужны явные проектные переопределения
  позиций или другой обратимый способ редактирования без второй модели.
- Плоский Project не предоставляет полноценную иерархию физических сборок.
- Артефакт ограничен 4000000 символами модели. 1024 устройства / 8192 сигнала
  дали 2676022 символа и прошли; 2048 устройств дали 5417078 символов и не
  прошли BuildArtifact validation.
- Browser QA проверил 130 устройств / 513 связей и мобильный toolbar. Routing и
  browser QA на тысячах устройств остаются непроверенными.

Следующий шаг по масштабу: виртуализировать/масштабировать оборудование на
сцене и измерить маршрутизацию и browser responsiveness на больших реальных
топологиях. Изменения передачи наблюдений должны сохранить качество,
происхождение и восстановление подписчика. Физические уравнения оборудования
при устранении этих ограничений не меняются.
