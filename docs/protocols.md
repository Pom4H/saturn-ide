# Протоколы как код проекта

`defineProtocol()` описывает способ обмена. `source.bind()` добавляет типизированный адрес
в существующий Signal/SignalSpec. `acquire()` исполняет эти привязки как обычный Driver.
Нет нового Project/Signal, глобального plugin manager или скрытой установки расширения.

## Использование

Скопировать `saturn-plugins/protocols/json-http.ts` в свой проект. Это небольшой работающий пример
**прикладного JSON/HTTP протокола**, не реализация API конкретного контроллера, Modbus или OPC UA.

```ts
// connections.ts
import { jsonHttp } from './plugins/json-http';

export const plc = jsonHttp('PLC-01', {
  url: 'http://127.0.0.1:9000/io', // адрес своего тестового endpoint
}, { pollMs: 250 });
```

```ts
// project.ts
import { project, pump, signal } from '@saturn/core';
import { plc } from './connections';

export const p1 = pump('P-01', {
  x: 100, y: 100, label: 'Насос',
  rpm: plc.bind(signal({ initial: 0, unit: 'rpm' }), { tag: 'speed' }),
  run: plc.bind(signal({ initial: false, writable: true }), { tag: 'run' }),
});

export default project({
  id: 'station', label: 'Станция', equipment: [p1], pipes: [], alarms: [],
});
```

```ts
// server.ts
import { acquire } from '@saturn/scada/acquisition';
import { plc } from './connections';

export default acquire(plc);
```

Это два публичных entry point существующих слоёв, не два новых пакета для установки.
Bun builder, Language Service и tsconfig разрешают их одинаково. По умолчанию source — live:
сборка/импорт не подключают сеть, live-применение остаётся явной операцией и требует lockfile.
`mode: 'simulation'` задаётся только для доверенного стенда/симулятора, не является авторизацией.

`P-01.rpm` материализуется владельцем, остаётся тем же сигналом для схемы, истории и отчётов.
Адрес `{tag:'speed'}` проходит TypeScript и runtime-проверку плагина. Определённый в проекте
`Signal.binding` — единственный авторский источник адреса; отдельного списка тегов для драйвера нет.
`initial` не публикуется плагином как измерение. У runtime пока остаются прежние stale-placeholder
с `at:0`; событие качества до первого показания не записывает их в историю.

## Новый протокол

Плагин экспортирует результат `defineProtocol({ id, address, connect })`.

`address(unknown)` проверяет и возвращает адрес своего типа. Это может быть строковый node ID,
объект `{unit, area, offset, format}` или другой JSON-адрес. Сам конструктор не интерпретирует
регистры, endian, scaling или binary framing: это обычный тестируемый код конкретного протокола.
Не нужен отдельный язык описания пакетов поверх TypeScript.

`connect(config, AbortSignal)` создаёт сессию. При отказе открытия плагин сам освобождает
частично полученные ресурсы. Сессия предоставляет **ровно один** способ получения данных:

| Метод | Контракт |
| --- | --- |
| `read(channels, signal)` | Один пакет чтений за итерацию. Адреса уже разобраны; каждый channel содержит существующий Signal. Группировку регистров/запросов реализует адаптер. |
| `subscribe(channels, emit, signal)` | Promise живёт до разрыва или отмены. Каждый `emit(batch)` нужно await. Преждевременное завершение считается разрывом. |
| `write(channel, value, signal)` | Необязательный путь команды. Тип/диапазон/writable проверяются до вызова. Успех операции не меняет Sample. |
| `close()` | Обязательное освобождение всех ресурсов и незавершённых операций. Rejected/timeout close запрещает повторное открытие. |

Вся сессия может быть написана на SDK нужного протокола, `fetch`, TCP/serial API.
Один цикл и одна очередь операций принадлежат соединению, а не каждому сигналу. Для нескольких
приборов на общей шине следует создать один source с адресами этих приборов, не независимые
конкурирующие соединения к одному порту.

Плагин может возвращать частичный пакет, если получены не все показания. Нельзя заполнять
пропуски нулями или initial. Для известной ошибки канала есть `{signal, quality:'bad'}` без value.
Пустой пакет/keepalive подтверждает только работу транспорта и не обновляет свежесть сигналов.
Если протокол действительно подтверждает неизменное значение, адаптер может явно повторно
передать его с исходным sourceAt и новым получением. Универсальной подмены keepalive измерением нет.

## Наблюдения

`Observation` — входная проекция существующего `Sample`, а не вторая модель значения.
Runtime принимает value, quality, sourceAt, receivedAt и sequence. `at` и semantic identity
назначает runtime. Пакет проверяется целиком до записи; чужие/повторные ID запрещены.
Тип значения и конечность чисел проверяются отдельно от технологических пределов: достоверные
105 градусов не теряются из-за предела 100. Команда за пределами диапазона по-прежнему запрещена.

`observe()` проходит через staging установки, проверку runtime, транзакцию архива и snapshot/SSE.
Старый `publish({id:value})` сохранён как value-only путь для существующих драйверов.
Новый acquisition driver требует observe-aware host, а не теряет метаданные молча.

`at` остаётся монотонной локальной шкалой событий архива, **не** гарантированным временем
измерения прибора. `sourceAt` сохраняется отдельно. Freshness использует receivedAt.
Quality-only событие сохраняет последнее значение и его receivedAt/sourceAt, но получает новый
момент события в архиве. Старые строки SQLite/PostgreSQL читаются после добавления details;
данные не удаляются. `state` вычисляется из компактного качества, чтобы поля не противоречили.

Пока нет дедупликации/backfill по sequence, выравнивания часов, полной семантики OPC UA StatusCode,
дискового store-and-forward или переноса sourceAt на основную временную ось отчётов. Само наличие
полей не означает, что эти возможности реализованы.

## Исполнение и отказы

До открытия проверяются отсутствующие/дублирующиеся владельцы и все адреса. Один source не
может публиковать сигналы другого. Опрос не перекрывается сам с собой; следующая задержка
начинается после завершения пакета. Read и write сериализуются на соединении. Количество
ожидающих записей ограничено; срок команды учитывает ожидание в очереди протокола.

Разрыв одного source не останавливает другие. Источники переподключаются с ограниченным
экспоненциальным backoff. Перед новым connect обязательно завершается close прежней сессии.
Отозванное поколение теряет право emit. Ошибка cleanup делает source faulted; stop сообщает
ошибку InstallationManager вместо запуска второго владельца оборудования.

AbortSignal/таймаут — кооперативная граница I/O, **не песочница для зависшего JS или стороннего SDK**.
Адаптер обязан прекращать операции и освобождать ресурсы. Код не обещает обратимость физических
действий и не подтверждает изоляцию процесса runtime — она остаётся отдельной задачей.

Ошибка или timeout отправленной команды может означать неизвестный физический результат.
Автоматического повторения записи нет. Успех HTTP/MQTT/другой доставки также не является
подтверждением положения исполнительного механизма: его подтверждает следующее наблюдение.

`driver.status()` возвращает состояние/попытки/последнюю ошибку/счётчик пакетов каждого source.
Это доступная программная диагностика; отдельная панель диагностики в Shell в этом изменении
не реализована. Архив всё ещё backpressure-зависим от доступности SQL; offline-buffer отсутствует.

## HTTP fixture

Пример делает один GET на пакет. Ответ:

```json
{
  "speed": {"value": 1400, "quality": "good", "sourceAt": 1720000000000, "sequence": 7},
  "run": {"value": false, "quality": "good"}
}
```

Команда — POST `{ "tag": "run", "value": true }` на тот же URL. Ответ 2xx означает только
принятие HTTP-запроса. Размер ответа ограничен 1 MiB, redirects запрещены. Для реального
развёртывания нужны HTTPS и свой механизм доступа; токен можно получать runtime-функцией
`token`, не помещая секрет в Signal.binding или Git. Этот пример не приписывается штатному PLC API.

## Проверки

`tests/acquisition.test.ts` проверяет декларативность, типы адресов/команд, опрос/подписки,
backpressure, ограниченную очередь, закрытие/переподключение, поздние callbacks и настоящий HTTP
на loopback. Это не испытание физического контроллера.
`tests/observations.test.ts` выполняет настоящий Runtime с fault-injected persistence adapter.
`tests/acquisition-integration.test.ts` добавляет Bun/SQLite migration, staging/fencing с bundle
и сборку внешнего проекта через оба публичных импорта. Запуск этих интеграций требует Bun.
