# Командная оболочка Saturn

Браузерный терминал, консоль OpenTUI и внешний CLI используют один `CommandShell`
из `src/shell/model/commands`. Каталог команд определяет аргументы, подсказки,
справку и класс действия. Ядро не импортирует React, Bun, DOM, compiler или runtime.
Host передаёт `ShellSession`, текущий серверный снимок и HTTP port.

## Запуск

```sh
SATURN_PROJECT=../saturn-examples/pumping-station bun dev
# В другом терминале:
bun cli                         # интерактивная командная оболочка
bun tui                         # проводник TUI; F7 открывает ту же консоль
bun cli --url http://127.0.0.1:3001
```

В браузере — вкладка «Терминал» общей нижней панели. Сворачивание и переключение
поверхности сохраняют ввод, журнал и историю в текущей сессии. Перезапуск процесса
или страницы пока не восстанавливает историю команд и несохранённые документы.
Выход из TUI не останавливает сервер. Ctrl Q при несохранённых документах требует
повторного нажатия; Ctrl C в консоли останавливает ожидание текущего запроса.

## Навигация и подсказки

```text
cd /runtime
signals P-01
get P-01.rpm
set P-01.run false
cd /
/project ports PLC-01
/project trace P-01.run
/project topology P-01
/project open P-01 source
```

Разделы: `/project`, `/runtime`, `/source`, `/reports`, `/git`.
Полный список и описания: `help`. Старые `set`, `signals`, `clear` сохранены.
Имена разделов относятся к операциям Saturn; оболочка не исполняет системные команды.

- Tab вставляет выбранное дополнение, не исполняя команду.
- ↑/↓ выбирают подсказку; при закрытом списке — историю.
- Shift Tab выбирает предыдущую подсказку.
- Enter исполняет введённую команду; Escape закрывает список.
- Ctrl P / Ctrl N листают историю, сохраняя незавершённый ввод.
- Ctrl R показывает историю с фильтром по текущему вводу.
- Ctrl L очищает журнал. В браузере Ctrl Space повторно вызывает подсказки.

Подсказки ресурсов используют существующий AST-каталог и реальные пути файлов.
Устройства, сигналы, порты и значения берутся из текущего проекта. Команда `set`
предлагает только writable-сигналы и проверяет тип/диапазон через `validateValue`.
Runtime повторно проверяет команду; клиент передаёт `expectedApplied`.
Показания обновляются только наблюдениями, ответ «принято» не меняет readback.

## Текстовый ввод с decision-моделью

Переключатель **Команда / Текст** находится в том же терминале. Текстовый режим
подготавливает существующую команду по естественному запросу, уточняет аргументы
и показывает предложение для отдельного подтверждения. Исполняет его текущий
`CommandShell`; браузерная навигация использует текущую `ShellSession`, не сессию
внешнего CLI. Без настроенного провайдера командный режим полностью работоспособен.

Локальный Kev, TypeSafe Jev, Vercel AI Gateway и собственный System One server
подключаются через настройки host. Подробности, границы передачи данных и проверки:
[Текстовые решения](decision-control.md). Генеративный ACP-агент остаётся отдельным
путём; старые `/ai` команды не возвращаются.

## TypeScript через Tab

```text
/project open P-01 source
/source insert equipment/P-01.device.ts end booster.ru
```

После `booster.ru` Tab дополняет `run` через настоящий TypeScript Language Service.
Поле кода после пути и позиции сохраняется буквально, включая кавычки и пробелы.
Enter вставляет код в общий `Documents`-черновик, сразу видимый в открытом редакторе.
Позиция — смещение UTF-16 от нуля или `end`. Дополнение не изменяет документ.

```text
/source diagnostics equipment/P-01.device.ts
/source read equipment/P-01.device.ts
/source save equipment/P-01.device.ts
```

Сохранение использует ту же проверку версии файла, что браузерный редактор.
Конфликт не уничтожает черновик. Save не вызывает publish/apply; существующий
автоматический preview доверенного симулятора управляется настройками host.
Полностью ручной режим: `SATURN_PREVIEW=manual`.

Это вставка кода с Language Service, а не универсальный AST-рефакторинг.
Здесь нет автоматического импорта, создания прошивки или исполнения написанного JS.

## Контекст проекта и внешний ACP

```text
/project context
```

`project context` возвращает ограниченную сводку выбранного устройства, портов,
топологии, текущих показаний, applied revision и изменений авторского источника.
Полные исходники, driver/config payload и session key в сводку не входят.
Интеграция IDE с агентом использует внешний ACP-клиент:

```sh
SATURN_PROJECT=../saturn-examples/pumping-station bun agent -- npx -y @agentclientprotocol/codex-acp
```

Агент запускается отдельно от runtime и использует собственные ACP permissions.
Встроенный генеративный provider/API для ACP Assistant в workspace host отсутствует.
Необязательный decision endpoint не предоставляет генерацию кода или native tools.
Браузерный host может передавать стандартные ACP события тому же внешнему агенту:

```sh
SATURN_PROJECT=../saturn-examples/pumping-station \
SATURN_AGENT_COMMAND='["npx","-y","@agentclientprotocol/codex-acp@2.0.1"]' \
bun dev
```

Команда задаётся локально, а не из browser request; запускается в workspace root.
Страница «Чат и поддержка» отправляет ограниченный `CommandShell.context()` вместе
с задачей, показывает текст/инструменты/запросы разрешения и ошибки ACP. Несохранённые
черновики обозначены путём/версией: агент читает файлы на диске, а не скрытую копию
редактора. Stop отправляет ACP cancel; Disconnect и shutdown закрывают процессы.
Локальный transcript временный; долговременная история и настройки принадлежат
внешнему агенту. Перезагрузка UI не восстанавливает его прежний разговор. Browser
reload закрывает transport запроса; некооперативная отмена внешнего инструмента
не гарантирует отмену его эффекта. Это локальный host adapter, не SaaS auth.


Для внешних агентов доступны тот же каталог, completion и структурированные результаты:

```sh
bun cli --schema
bun cli --json runtime signals P-01
bun cli --complete 'set P-01.run '
bun cli --cwd /runtime --complete 'se'
bun cli --json --batch < commands.txt
```

`--schema` не требует сервера. Остальные команды подключаются к workspace host.
`--complete` принимает необязательный `--cursor` в пределах командной строки.
Обычный результат: `{ ok, command, text, data, effect }`; код выхода ненулевой при
ошибке. Классы действий: read, navigate, draft, save, control. Они описывают
действия для вызывающего агента; серверные проверки полномочий сохраняются.

В batch каждая строка — команда или JSON-строка с командой (для многострочного кода).
Одна сессия сохраняет черновики между строками; первая ошибка останавливает batch. Отдельный одноразовый `source insert`
возвращает изменённый source в `data`, но не пишет файл: для последующего save нужен
тот же batch/интерактивный сеанс. Внешний CLI обновляет snapshot перед каждой командой.
Автоматического повтора управляющих действий нет.

Оболочка подключается к существующему workspace HTTP API. Авторизация отдельного
runtime-only host и SaaS требует соответствующего transport adapter; этот CLI не
обходит их роли и не заявляет поддержку всех deployment targets.
