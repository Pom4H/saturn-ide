# Saturn IDE

Инженерный проект на TypeScript. Shell объединяет схему, исходники, сигналы, HMI, отчёты и среду исполнения. Один локальный процесс Bun обслуживает интерфейс, SCADA, SSE, SQLite/PostgreSQL, Git и Web Push. Лендинга нет.

```sh
bun install
bun dev
```

Откройте `http://localhost:3000`. Нужны Bun 1.4.2+ и Git. SQLite создаётся автоматически в `.saturn/`.

```sh
DATABASE_URL=postgres://user:password@localhost:5432/saturn bun dev
SATURN_PROJECT=./project PORT=3001 bun dev
```

## Shell

Постоянные контексты — проект, рабочий раздел и среда. Симуляция обозначена явно. Слева находятся разделы и дерево проекта; внутри схемы — только 2D/3D, масштаб, порты и переключение кода. Справа можно открыть свойства выбранного оборудования. Тревоги относятся к runtime и открываются нижней панелью.

`Ctrl/⌘ K` открывает поиск разделов, оборудования и файлов. `Ctrl/⌘ B` переключает дерево, `Ctrl/⌘ J` — тревоги, `Ctrl/⌘ S` сохраняет текущий исходник. Файлы открываются вкладками; несохранённые буферы остаются при переключении. Для крупных экранов код и схема доступны рядом. Операторский режим скрывает инструменты разработки, но **не является системой разграничения прав**.

Выбор насоса показывает его сигналы, подключённые трубы и кабели, связанные отчёты и переход к исходнику. Из сигнала можно открыть архивный график. Git показывает настоящий diff и последние коммиты. Коммит не захватывает staged-файлы за пределами каталога проекта; pull допускает только fast-forward. Необходимо настроить `git config user.name`, `user.email`, remote и авторизацию Git.

В разделе «Среда» Git-черновик и текущая модель runtime показаны отдельно. Публикация на удалённый объект не реализована и не изображается как применённая версия.

## Типы выводятся из проекта

`project()` сохраняет конкретный тип определения, а не расширяет его до общего `Project`. Сигналы сохраняют ID, тип значения и возможность записи. Фабрики оборудования сохраняют конкретные сигналы; имена портов известны компилятору.

```ts
const run = signal('pump.run', { initial: false, writable: true });
const rpm = signal('pump.rpm', { initial: 0, unit: 'rpm' });
const booster = pump('P-01', { label: 'Насос', x: 335, y: 190, rpm, run });
const controller = plc('PLC-01', {
  label: 'ПЛК', x: 670, y: 335,
  online: signal('plc.online', { initial: false }),
});

command(run, true);       // допустимо
// command(run, 12);      // ошибка: ожидается boolean
// command(rpm, 1200);    // ошибка: сигнал только для чтения

cable('start', { from: controller.ports.DO1, to: booster.ports.run, signal: run });
// controller.ports.missing — ошибка имени порта
// pipe(... DO1 ...) — электрический порт не является трубным
```

Все использованные сигналы включаются в `project.signals`. На HTTP-границе типы и диапазоны проверяются повторно. `observation(snapshot, signal)` выводит тип показания из сигнала и не заменяет отсутствующее показание начальным значением. `SignalValues<typeof signals>` и `ReportRow<typeof report>` выводят структуры без повторных интерфейсов.

CodeMirror использует настоящий TypeScript Language Service. Автодополнение работает после `.` для сигналов, оборудования и портов. JSDoc выбирается из `@ru`/`@en` исходных объявлений; собственного словаря DSL-подсказок нет. Доменные ошибки локализованы; сообщения компилятора остаются оригинальными.

### Актуальные зависимости и TypeScript 7

Использованы проверенные актуальные релизы React **19.3.0**, Three **0.186.0**, Playwright **1.63.0**, обновлённые пакеты CodeMirror 6 и Bun **1.4.2**. `web-push` **3.6.7** и базовый `codemirror` **6.0.2** оставлены: в проверенных upstream package.json это текущие версии, а не произвольные старые фиксации.

Native TypeScript **7.0.2** установлен как `@typescript/native`; `typescript` — официальный совместимый alias `@typescript/typescript6@6.0.2`. `tsc` проверяет проект версией 7, `tsc6` — версией 6, чьи стабильные AST/Language Service API используют редактор и source editing. У TS 7 API отличается; простая подмена старого пакета ломала бы IDE. Устаревший `baseUrl` удалён. `bun run check` запускает обе проверки.

Версии сверены 23 сентября 2026: npm registry React/TypeScript, официальный анонс TypeScript 7, GitHub release r186 / package.json Three, release Playwright и upstream package.json CodeMirror. Диапазоны `@types/*` выбирают совместимые опубликованные типы; точные транзитивные версии должен зафиксировать **реальный `bun.lock` после успешной установки**, не сгенерированный вручную. Обновление выполняется явно: `bun run deps:update`, затем проверки.

## 2D, 3D и физическая топология

Порты определены один раз: координаты XYZ, сторона выхода, среда, семейство, направление и допустимая занятость. `pipe` соединяет жидкостные выход/вход. `cable` — совместимые электрические/управляющие/шинные порты. Направление, семейство и занятость проверяются типами и runtime. Пересечение линий не создаёт соединения; кабельная трасса не является симуляцией PLC-протокола.

Ортогональный маршрутизатор обходит габариты оборудования, сохраняет нормаль выхода и точную высоту концов. `via` задаёт промежуточные точки. Непроходимая трасса явно помечается ошибкой, а не рисуется как корректная. Бюджет MVP — 128 устройств, 512 соединений и 40 000 шагов поиска на трассу. Не реализованы автоматическое размещение оборудования, минимизация всех пересечений и полный набор старых extension-defined профилей.

В 2D сохранены детальные исходные SVG насоса, резервуара и клапана. Перемещение меняет числовые диапазоны AST, не форматирует файл заново. Координаты и трассы обновляются до drop; отпускание сохраняет файл. Escape отменяет движение. Вычисляемые координаты не переписываются. Undo объединяет жест в одно изменение. Файл сохраняется с проверкой версии; конфликт возвращает 409.

3D — настоящий Three/WebGL с камерой, материалами металла и воды, тенями, разрезами резервуара и насоса, ротором и индикатором клапана. Трубы/кабели используют **тот же рассчитанный маршрут** и XYZ-порты. В 3D можно вращать камеру и выбирать оборудование; перемещение исходных координат пока выполняется в 2D. Модель строится заново при изменении проекта, а телеметрия обновляет анимацию без перестройки сцены. GPU-ресурсы освобождаются при закрытии представления.

Фаза движения интегрируется во времени. Команда не подменяет показание. При устаревшем расходе или закрытом клапане движение жидкости останавливается; недостоверные значения не выглядят исправными. Поддерживается системная тема и reduced motion. Совпадение визуального качества со всеми прежними сценами **не подтверждено без браузерного прогона и просмотра результата**.

## Отчёты

Отчёты определяются теми же сигналами проекта:

```ts
report('hourly-water', {
  label: { ru: 'Почасовой расход воды', en: 'Hourly water balance' },
  bucketMs: 3_600_000,
  columns: {
    volume: column(signals.flow, 'integral', { ru: 'Объём', en: 'Volume' }, 'm³'),
    meanFlow: column(signals.flow, 'mean', { ru: 'Средний расход', en: 'Mean flow' }, 'm³/h'),
    peakPressure: column(signals.pressure, 'max', { ru: 'Макс. давление', en: 'Peak pressure' }, 'bar'),
  },
});
```

Раздел «Отчёты» выбирает определение и период, обращается к SQL-архиву, показывает таблицу, долю достоверного покрытия каждого значения, время формирования и ревизию модели. Есть CSV и печатный стиль. CSV можно открыть в Excel; это не генерация XLSX. Пользовательские строки защищены от интерпретации как формулы.

`mean` взвешен по времени, `integral` интегрирует **скорость в единицах за час**. Для m³/h результат — m³. Алгоритм удерживает последнее достоверное значение только до следующего измерения или `staleAfter`. Пропуски не заполняются нулями. При отсутствии данных результат `null`; частичный интеграл явно сопровождается coverage. Период — `[from,to)` UTC; окна отсчитываются от выбранного `from`, последнее может быть неполным. Это интервальные окна, не локальные календарные часы с DST.

`GET /api/report?id=hourly-water&from=<epoch-ms>&to=<epoch-ms>` возвращает JSON; `&format=csv&locale=ru` — CSV. Отчёт читает диапазон и предшествующее измерение, а не последние 300 точек графика. Ограничения интерактивного запроса: 31 день / 1000 окон, 50 000 измерений на сигнал и 200 000 суммарно; превышение возвращает ошибку, не обрезанный отчёт. UI предлагает последние 1/6/12/24 часа. Планировщик, конструктор произвольных печатных форм и XLSX ещё не реализованы.

## Файлы проекта и расширения

```text
project/
  project.ts
  server.ts
  plugins/
    simulation.ts
  equipment/<device>/
    device.ts
    hmi.ts
    compiler.ts
    firmware/
```

```sh
bun run scaffold plc plc-01
bun run scaffold plugin pressure-switch
bun run scaffold project ../another-station
bun run firmware equipment/plc-01
```

Плагины копируются и импортируются обычным TypeScript. Нет manifest, marketplace, контейнера зависимостей или глобальной регистрации. Генератор не перезаписывает существующие каталоги. Прошивка компилируется только явной CLI-командой; шаблон требует настоящего toolchain конкретного ПЛК и не создаёт фиктивный `.bin`.

`/hmi` использует тот же SVG и проект, с навигацией и управлением. Это браузерное представление, а не физический дисплей, прошивка или эмулятор микроконтроллера.

## Сервер и граница MVP

Bun.serve обслуживает React/CodeMirror, SSE, SCADA, Git и Web Push с одного origin. Bun.SQL выполняет параметризованные запросы SQLite/PostgreSQL без ORM. БД содержит измерения, события тревог и push-подписки; проект в БД не дублируется. История по умолчанию хранится семь дней, журнал тревог сохраняется.

SSE восстанавливает полный снимок при переподключении. Квитирование не снимает причину тревоги. После перезапуска старые измерения считаются stale до подтверждения драйвером. Ошибка исходника оставляет последнюю корректную модель. Изменение схемы не перезапускает сбор данных. Команды подтверждаются последующим наблюдением драйвера.

POST требует JSON и `X-Saturn-Key` из `/api/state`. Проверяются Origin/Host, пути, версии файлов и значения. IDE привязана к `127.0.0.1`; это **не публичный multi-user сервер**. TypeScript, драйверы и build scripts выполняются с правами пользователя: открывайте только доверенные проекты. Физические промышленные драйверы, HA, safety-контроллер, удалённые роли и управляемое развёртывание не заявляются.

Web Push генерирует локальные VAPID-ключи и сохраняет подписки. Нужны разрешение пользователя, поддерживаемый браузер, secure context и доступ к push-провайдеру; доставка на физическое устройство тестами не имитируется.

## Проверка

```sh
bun run check
bun test tests
bunx playwright install chromium
bun run test:browser
```

Для PostgreSQL: `TEST_POSTGRES_URL=postgres://... bun test tests`. Без URL соответствующие тесты явно пропускаются. Один CI job поднимает PostgreSQL, выполняет проверки и записывает только реальные browser screenshots в `artifacts/`.

Фактически выполненные проверки и непройденные этапы записаны в `docs/verification.md`. Написанный тест не означает успешно выполненный тест.
