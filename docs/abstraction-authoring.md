# Абстракции по мере необходимости: граница DSL → Shell

Срез: 2026-10-23, исходная ревизия `11807a121e01c73afbebbc6c77644e1721466cbd`.

## Принцип

Инженер вводит понятие, когда оно помогает решить задачу. Обычная TypeScript-функция
или проектная фабрика `device()` не требует нового класса в ядре, записи в registry,
отдельного manifest либо файла на каждый прибор. Один файл может описывать объект
целиком; несколько файлов могут группировать его по смыслу.

Shell редактирует тот же исходник через существующие AST-операции и CAS. Общая фабрика
не становится второй моделью и не даёт полномочий управления установкой. Сохранение
не означает check/publish/apply. Этот инкремент не меняет runtime и не вводит SDK плагинов.

## Найденные и исправленные разрывы

1. `dslCatalog` принимал `project.ts`, но находил в нём только тревоги: оборудование
   требовало окончания `.device.ts`. Теперь явные экземпляры распознаются и в обычных
   авторских TS/TSX-модулях, включая `project.ts` и `systems/line.ts`.
2. Общий AST-поиск брал первое поле, инспектор — последнее, а каталог предложений
   запрещал любой spread. `authoredProperty` задаёт одно консервативное правило
   определения поля для этих путей. Явный override после defaults доступен;
   потенциально перекрытое поле не становится целью обратного редактирования.
3. Обход находил экземпляры внутри функций/методов. Теперь их тела пропускаются:
   изменение общего шаблона не подменяет изменение одного экземпляра.
4. Разворачивался произвольный метод `.bind`, но не импортированный `bind()` из core.
   Теперь распознаются именно импорты core, их aliases и namespaces. Сигнал с явным ID
   сохраняет этот ID; поле сигнала в кавычках не теряется. Type-only imports не дают
   каталогу вызываемых функций.

Пример допустимого override:

```ts
const inlet = sensor('PT-01', {
  ...defaults,
  label: 'Давление на входе',
  x: 120,
  y: 80,
});
```

`x: 120, ...defaults` не даёт надёжного обратного отображения на значение экземпляра.
Дубли полей, computed keys, shorthand/accessors и локализованные подписи проверяются
тем же правилом. Неопределённость не устраняется вставкой нового override из инспектора.
Изменение шаблона или вычисления остаётся явной правкой TypeScript.

## Границы

Каталог предложений по-прежнему ограничен литералами подписи, начального значения
сигнала и порога тревоги, 1–8 операциями и единственной однозначной целью.
Исходники vendor plugins, firmware, targets, protocols, зависимостей, тестов, скриптов
и runtime/browser/driver entrypoints не получают доступ к этому пути правки.
Это фильтр authoring API, не sandbox исполнения и не замена авторизации host.

Структурное распознавание `factory('ID', { x, y, ... })` не является доказательством
обратимости произвольной TypeScript-программы. Вычисленные экземпляры, замыкания,
параметрические генераторы и полноценный Shell contribution SDK этим изменением
не объявляются поддержанными. Вызовы, преобразующие координаты/ID внутри фабрики,
по-прежнему требуют отдельной проверки source mapping.

## Проверка

Исходные четыре модуля, включая неизменённый `workspace/files.ts`, восстановлены из
GitHub и побайтно сверены по Git blob SHA. Проверены настоящие AST/property/proposal
функции и Workspace с временными файлами: обнаружение координат → инспекторная правка
→ сохранение с CAS → повторное обнаружение; устаревшая версия отвергается.

Среда: Linux, Node **22.16.0**, TypeScript **5.8.3**.

- 16 новых тестов `tests/abstraction-authoring.test.ts`: до исправления **2 pass / 14 fail**,
  после **16 pass / 0 fail**.
- Три существующих `tests/dsl-proposal.test.ts`: **3 pass / 0 fail**. В проверке
  перекрытой локализации spread перенесён после литерала; обратный, допустимый
  порядок отдельно покрыт новым тестом.
- Совместный прогон: **19 pass / 0 fail**. В локальном runner импорт `bun:test`
  заменён на `node:test`; expect трёх старых тестов отображён на `node:assert/strict`.
  Продуктовые модули транспилированы без подмен. Это **не штатный Bun-прогон**.
- Отдельный strict typecheck `workspace/ast.ts` на TypeScript 5.8.3 и
  `git diff --check` прошли.

Команды штатной проверки, которые в этой среде не выполнялись:

```sh
bun run check
bun test tests/abstraction-authoring.test.ts tests/dsl-proposal.test.ts tests/entity-ux.test.ts tests/source-authoring.test.ts tests/refactor.test.ts
bun test tests
```

Bun 1.4.2, TypeScript 7/6, полный architecture check, браузерный drag/undo и весь
build → runtime сценарий ещё требуют проверки на этой ревизии. Новые workflow и
дополнительные CI-запуски для этого инкремента не создавались.
