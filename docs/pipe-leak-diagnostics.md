# Поиск подозрительного участка трубопровода (оператор)

Приоритет: безопасный поиск **участка**, а не выдумывание точки разрыва.
Топология Project описывает инженерные соединения, не подтверждает сама по себе
физическую сборку. Импорт IFC может дать привязку к зданию, но геометрия не
является датчиком утечки.

## Минимальные достоверные данные

На **каждой** трубе, которую хотим локализовать, требуются два независимых
расходомера на границах физического участка, одинаковые единицы измерения
и сопоставимые часы измерений. Один расходомер на насосе, один датчик давления
или повторное использование одного общего расхода у нескольких труб не
позволяют доказать, где произошёл разрыв. Направление измерения — от `from`
к `to`; при обратном направлении сравнение помечается недостоверным.

```ts
const segment=pipe('discharge',{
  from:pump.ports.outlet,to:valve.ports.inlet,
  flow:pump.flow,
  leak:{
    inlet:dischargeInletFlow, outlet:dischargeOutletFlow,
    maxLoss:0.5, // в общих единицах расхода
    maxSkewMs:500,
  },
});
```

Это авторская декларация на обычной Pipe. Оба измерения входят в Project.signals,
checked BuildArtifact, семантический граф и runtime snapshot. Никакой скрытой
таблицы датчиков/труб и отдельной редакторской модели не создаётся.

## Диагноз и UX

`diagnosePipeLeaks` — чистая проекция Applied Project + Snapshot, без
команд, записи событий или создания сигнала из `initial`.
Результат на участок: **возможная утечка** (входной расход существенно
больше выходного), **в пределах допусков**, **нет наблюдения** (нет/плохие/
устаревшие/несинхронные/подставленные измерения, обратный расход), или
**не оснащён датчиками**.

Оператор открывает «Трубопроводы» в HMI, видит текущие измерения,
расхождение, порог и конкретный `pipe.id` на схеме. Подозрение
подсвечивает только authored трубу, не соседние IFC/CAD линии. Если датчиков
недостаточно, показывается «Нельзя определить участок», а не «всё в норме».
В режиме симулятора вывод явно остаётся симуляцией.
Подсветка по двухдатчиковому балансу **не подтверждает физическое место пробоя**
и не должна автоматически закрывать арматуру.

Следующая ступень для больших установок: sensor coverage каждого сегмента,
обратная реконструкция сети с ветвлениями/резервуарами, тренды/устойчивость
аномалии, контекст закрытых клапанов, давления/температуры и подтверждённые
CAD/IFC координаты помещения/этажа. Историческое сравнение и автоматический
поиск места течи **не заявляются готовыми**.

## Приёмка

- Сегмент 1 нормальный, сегмент 2 с дисбалансом: в HMI выделен только №2;
- при потере связи, плохом качестве или рассинхронизации — не угадывать;
- один расход на две трубы — только «нет локализации»;
- выбрав трубу в списке или схеме, оператор видит два конца и показания;
- изменения DSL проходят обычный check/Git/publish/apply, UI не вызывает
  управляющие команды автоматически;
- мобилка и полноразмерный HMI используют одну локализацию и читаемые подписи.
