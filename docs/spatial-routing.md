# Высота помещений и пространственные проходы

Группа `system()` может задавать отметку пола и именованные места прохождения труб
или кабелей. Они принадлежат исходному TypeScript-проекту. Маршрутизатор, 2D/3D,
семантическое ревью и BuildArtifact используют те же объявления.

```ts
import { project, system, tank, pump, plc, signal, pipe, cable } from '@saturn/core';

const floor = system('floor-2', { label: 'Второй этаж', z: 300 });
const room = system('pump-room', {
  label: 'Насосная',
  parent: floor.id,
  z: 0,
  ports: {
    water:   { medium: 'fluid',   x: 600, y: 450, z: 120 },
    control: { medium: 'control', x: 620, y: 80, z: 180 },
  },
});

const reservoir = tank('T-01', { label: 'Бак', x: 50, y: 200 });
const motor = pump('P-01', {
  label: 'Насос', system: room.id, x: 850, y: 220, z: 20,
});
const controller = plc('PLC-01', { label: 'ПЛК', x: 200, y: 20 });
const flow = signal('flow', { initial: 0, unit: 'm³/h' });

const water = pipe('feed', {
  from: reservoir.ports.outlet,
  to: motor.ports.inlet,
  flow,
  nominalDiameterMm: 50, // DN — обозначение, не наружный размер
  outerDiameterMm: 60.3,  // фактический наружный Ø в миллиметрах
  via: [room.ports.water, { x: 750, y: 450, z: 420 }],
});
const control = cable('enable', {
  from: controller.ports.DO1,
  to: motor.ports.run,
  signal: motor.run,
  via: [room.ports.control],
});

export default project({
  id: 'plant', label: 'Установка', systems: [floor, room],
  equipment: [reservoir, motor, controller], pipes: [water], cables: [control],
});
```

## Координаты

Все координаты используют существующие **единицы схемы**. Это не объявление
масштаба в метрах или миллиметрах. X/Y остаются координатами плана проекта; они
не отсчитываются от автоматически вычисленной рамки группы.

`system.z` — смещение пола относительно родителя, либо мирового нуля для корневой
группы. `equipment.z` — высота основания оборудования относительно пола его
`system`; у оборудования без группы — мировая отметка. `ports[name].z` — высота
прохода над тем же полом. Полная иерархия суммируется. В примере пол насосной
находится на отметке 300, основание насоса — 320, проход воды — 420.

Литерал `{x,y,z}` в `via` задаёт **мировую** точку. Литерал `{x,y}` сохраняет прежнее
поведение: автоматическую высоту трассы по более высокому конечному порту. Список
`via` задаёт последовательность обязательных точек, в том числе вертикальные
участки с одинаковыми X/Y и разными Z. Отрицательные мировые отметки допустимы,
включая свободные `free()` концы в подвале.

Старый вызов `system('id', 'Название', 'parent')` остаётся допустимым; отсутствие
`z` означает ноль. Декларация помещения с проходами видна даже без оборудования.
Изменение отметки пола перемещает его оборудование и терминалы, но **не** перемещает
неприкреплённый `free()` конец: у него уже сохранена независимая мировая позиция.

## Проход — не соединение

`room.ports.water` — точка, через которую проходит существующая труба, а не
гидравлический узел. Аналогично кабельный проход не объединяет электрические цепи.
Два кабеля через один проход остаются двумя кабелями. Для тройника нужен `tee()`,
для подключения к прибору — его обычный `equipment.ports.*`.

Среды `fluid`, `control`, `power`, `bus` проверяются статически и при проверке
проекта. Проход питания нельзя передать трубе, а неизвестное имя порта — валидному
проекту. Проход не подменяет совместимость семейства и направления конечных
разъёмов оборудования.

`pipe()` и `cable()` сохраняют в `via` символическую ссылку
`{kind:'route-port',system,port,medium}`. Позиция хранится только у помещения.
Перенос прохода в исходнике перестраивает использующие его трассы без обновления
копий координат. Кэш маршрутов учитывает разрешённые мировые точки и отметки
родительских групп; скругление не срезает обязательные точки.

## Исполнение и границы

Правка пола или прохода меняет исходник/Checked-проекцию. Она сама по себе не
публикует проект, не применяет его к установке и не отправляет команд оборудованию.
В 3D меняются положения существующих meshes, а не создаётся вторая модель объекта.
2D показывает те же проходы с абсолютной отметкой Z. Визуальное перетаскивание
оборудования продолжает менять только его авторские X/Y.

## Диаметр трубы и CAD-масштаб

`nominalDiameterMm` — DN, номинальное обозначение. `outerDiameterMm` —
**фактический наружный диаметр**, именно он задаёт размер 2D-линии и 3D-трубы.
Смешивать эти значения нельзя. Это обычные поля `pipe()` в исходном TypeScript,
которые проходят типизацию, `validateProject`, Checked BuildArtifact и Git diff.

Когда в проекте есть **однозначный масштаб** импортированной CAD-модели
(`coordinates.displayScale` — единиц схемы на метр), диаметр в миллиметрах
переводится в радиус схемы как `outerDiameterMm * displayScale / 2000`.
3D использует этот же радиус; перевод плана в мировые координаты не создаёт
второго описания трубы. При отсутствии CAD-масштаба исходный размер сохраняется,
но толщина остаётся **условной**, без притворной физической точности.

IFC-импортер считывает `OuterDiameter`, `InnerDiameter` и
`NominalDiameter` только из явно связанных
`Pset_PipeSegmentTypeCommon` или диаметр круглого
`IfcCircle(Hollow)ProfileDef` в `Body` / `IfcExtrudedAreaSolid`.
Каждое подтверждение содержит STEP ID. Неизвестные единицы и противоречия
диагностируются: DN никогда не заменяет неизвестный наружный Ø.
CAD остаётся справочной подложкой, **автоматического переноса размера в authored Pipe нет**.
Инженер может выделить трубу и ось IFC, затем явно принять её Ø:
это CAS/AST-правка исходника, а не создание связи с CAD или команда контроллеру.

Это координатный контракт, **не BIM-модель стен и перекрытий**. Автоматический
обход оборудования использует консервативные XY-зазоры, увеличенные с учётом
известного наружного радиуса трубы при явном CAD-масштабе. Он может
отклонить путь при наложении оборудования разных этажей в плане: это не доказанный
трёхмерный конфликт. Высота не разрешает молча игнорировать препятствие. Толщина
стен, размеры отверстий, радиусы изгиба, кабельные лотки и монтажная приёмка не
выводятся из рамки группы и здесь не заявляются реализованными. XYZ и порядок
точек сохраняются точно в модели; поверхность трубы остаётся графической
аппроксимацией, а не метрологическим доказательством монтажа.

Проверки: `tests/spatial-routing.test.ts`, `scripts/spatial-browser-test.ts`.
