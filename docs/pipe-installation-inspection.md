# UX-PIPE-INSTALL-1 — геометрическая проверка труб и фитингов

Срез: 2026-10-11. Продолжение UX-PIPE-SIZE-1 / UX-ROUTE-1. Это read-only
инженерная проверка заданной геометрии, не разрешение на монтаж и не проверка
соответствия отраслевым нормам. Основная архитектура Project / source / runtime сохранена.

## Что реализовано

В общем инструменте выбранной трубы в 2D и 3D есть раскрываемая проверка геометрии.
Инженер задаёт минимальный зазор и минимальный радиус из требований проекта или
производителя. Пустое поле — неизвестное требование, а не ноль и не «норма по умолчанию».
Параметры этого диагностического запуска не сохраняются в TypeScript. Источники,
connectivity, publish/apply и команды контроллеру проверка не меняет.

Ядро считает расстояние между осевыми линиями в **XYZ**, вычитает оба фактических
наружных радиуса и сравнивает оставшийся зазор с заданным. DN в геометрии не участвует.
Проекция двух линий может пересекаться на плане, но при достаточном разносе по Z
между трубами нет конфликта. Неполный набор трасс, отсутствие масштаба/диаметра,
непереданные фитинги и исчерпание вычислительного бюджета никогда не дают `clear`.

`routeGeometry()` — общая чистая геометрия с существующим 3D-рендерером.
Она сохраняет нынешние квадратичные Bézier-изгибы, не выдавая их за круглые заводские
отводы. Для прямоугольного изгиба минимальный радиус кривизны равен `inset / sqrt(2)`,
а не `inset`. Проверяется реальная минимальная кривизна этой кривой, включая
ограничение по длине соседних сегментов. Символические проходы остаются точными
ограничениями: угол в таком месте не закругляется скрытно.

Кривые дробятся с аналитической границей отклонения от хорд. Для зазора выдаётся
интервал, а не якобы точное число по грубой сетке. Если порог попадает в интервал
погрешности, статус — `incomplete`. При ограничении количества проверок неизученные
пары не превращаются в свободное пространство.

Фитинг передаётся как консервативная пространственная капсула с фактическим
наружным размером и ссылкой на источник размеров. Его порты явно указывают трубу,
конец и наружный присоединительный размер. Разный диаметр порта и трубы — отдельная
диагностика. Разрешён только локальный контакт присоединённого конечного сегмента;
остальная труба не исключается из коллизий лишь потому, что имеет общий фитинг.

## Контракт расширения

Доступ через существующий публичный `saturn-ide/inspection`:

```ts
import { inspectPipeInstallation, inspectProjectPipeRoutes } from 'saturn-ide/inspection';

// actualRoutes — текущая проекция имеющегося topology solver, не второй Project.
const report = inspectProjectPipeRoutes(project, actualRoutes, {
  minimumGapMm: 25,       // пример явно заданного требования, не отраслевой норматив
  minimumBendRadiusMm: 100,
  fittings: verifiedFittingEnvelopes,
});
```

`inspectPipeInstallation()` также работает с readonly-проекцией осевых линий,
диаметров и масштабов. Формат не содержит React, Three.js, БД, сетевых соединений
или собственной регистрации оборудования. Плагин CAD отвечает за происхождение
геометрии; ядро — за численный расчёт; Shell — за ввод требований и диагностику.

API принимает именно переданные маршруты и не перепрокладывает их самостоятельно.
Встроенный компактный инспектор пока строит **новый кандидат** по текущей модели
через существующий solver: это явно подписано в UI. Кэшированный коридор на холсте
не изменяется. Для проверки именно текущего drag-коридора host может передать
`routes` в `PipeRouteInspection`. Автоматической проверки на каждом pointermove нет.

## Ограничения, которые нельзя скрывать

Не проверяются самопересечения одной трубы, стены/перекрытия, опоры, теплоизоляция,
провисание, давление/температура, материал, болтовой крепёж и монтажные допуски.
Капсула — внешний консервативный габарит, а не точный B-Rep фитинга. Данные фитингов
не извлекаются из текущего Axis-only IFC автоматически; без них инспектор показывает
неполную проверку. Список `fittings: []` означает, что вызывающий явно ограничил
проверку сценой без фитингов, а не что импортёр доказал их отсутствие.

Результат не является разрешением на runtime apply. В UI он сбрасывается при смене
объекта модели, маршрутов или требований. Функции API возвращают снимок результата;
вызывающий обязан инвалидировать его при изменении входов.

## План и приёмка

- [x] Чистое вычислительное ядро и общий с рендерером способ построения изгиба.
- [x] XYZ-зазоры, фактическая кривизна, габариты фитингов и присоединительные размеры.
- [x] Явная неполнота при недостающих данных, погрешности и ограничении бюджета.
- [x] Контекстная read-only проверка в существующем инструменте трубы; без новых глобальных панелей.
- [x] Локальные Node.js тесты вычислительного ядра и строгая компиляция TypeScript.
- [ ] Полный Bun/архитектурный CI и браузерная приёмка на self-hosted runner.
- [ ] Передать текущий view/drag route projection из обоих canvas напрямую в инспектор.
- [ ] Привязать требования к source-owned спецификации изделия и импортировать реальные габариты фитингов.
- [ ] Добавить монтажные радиусы как реальные круговые отводы; не менять тип изгиба незаметно.

Основания для терминов IFC: `Pset_PipeSegmentTypeCommon` различает NominalDiameter,
OuterDiameter и InnerDiameter; `Pset_PipeFittingTypeBend` / IFC4.3 `Pset_FittingBend`
задаёт BendRadius отдельно. Никаких универсальных множителей диаметра из этих
описаний не следует.
