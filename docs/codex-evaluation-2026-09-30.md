# Codex в Saturn: подключение и проверка помощи

Проверка 30 сентября 2026 года: macOS arm64, Bun 1.4.2, Node 26.4.0,
локальный Chromium/Playwright. Настоящий внешний агент:
`@agentclientprotocol/codex-acp@2.0.1` с bundled `@openai/codex`.
Общая конфигурация Codex выбирает `gpt-6.1-sol`, reasoning medium;
Saturn не переопределял модель и авторизацию.

## Подключение

`src/host/agent.ts` — транспорт стандартного ACP SDK 1.5.0 между локальным
внешним процессом и браузером. `SATURN_AGENT_COMMAND` задаёт команду массивом
аргументов; браузер не выбирает executable, cwd, env или модель. Процесс работает
в существующем workspace root. Чат использует ограниченную сводку общего
`CommandShell.context()`, включая качество показаний, Applied и признаки
несохранённых файлов. Source/runtime credentials в эту сводку не включены.

UI показывает текст, текущий инструмент, стандартные ACP permission options,
ошибки и отмену. Разрешение явно передаётся внешнему агенту; Saturn не добавляет
собственный tool loop. Ответы форматируются безопасным React Markdown renderer;
ссылки на реальные файлы каталога открывают общий редактор. История отображения
временная; auth, модель и durable agent sessions принадлежат Codex. Host ограничивает
число соединений шестнадцатью и закрывает неактивные процессы через десять
минут; новый UI после reload начинает новую внешнюю сессию.

Системный Codex 0.39.0 не смог прочитать существующую конфигурацию
(`missing field command in mcp_servers.surrealdb`). Современный адаптер подключился
с bundled Codex и существующей авторизацией. Общая конфигурация пользователя
не переписывалась. Адаптер установлен только в ignored `.saturn/codex-acp`,
не включён в зависимости или авторские исходники объекта.

## Оценка

В этой ограниченной проверке Codex достаточно хорошо помогает инженеру:
объясняет фактический источник, находит несоответствия топологии и поведения,
различает симуляцию и свежие показания, делает точную небольшую правку и честно
сообщает результат проверки. Короткий запрос даёт более удобный ответ: первый
CLI разбор без ограничения длины был чрезмерно подробным. Дополнительная
финальная проба с фразой «не запускай команды» не дала ответа по файлу:
агент воспринял её как запрет shell-чтения, попытался обратиться к состоянию
интерфейса, получил отказ автоматической проверки и честно остановился.
После явного разрешения обычных команд чтения файла финальная проба прошла.
Практическая формулировка read-only задачи: разрешить чтение исходников и
отдельно запретить runtime commands/publish/apply/deploy. Это ограничение
проверенного поведения, а не основание объявить весь агент надёжным.

Ответы не следует считать приёмкой оборудования или подтверждённым диагнозом
физической установки. Проверены один небольшой проект, одна модель и одна
простая правка; multi-file refactor, сложные reports/PLC targets, неизвестный
project-owned equipment, длинные разговоры и большие проекты отдельно не
оценивались. Ограниченный browser context отмечает несохранённый черновик, но
не передаёт его текст: агент читает сохранённый source. Существующие
архитектурные/физические критерии из capabilities.md остаются открытыми.
