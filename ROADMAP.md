## EXT-AUTHORING-1 — новые понятия без специальных веток в ядре

**P0, код и ограниченная локальная проверка 2026-10-23.**
[Разбор исправлений, границ и результатов](docs/abstraction-authoring.md).

- [x] Убрать требование `.device.ts` из каталога правок оборудования. Явные экземпляры
  проектных фабрик доступны в `project.ts` и обычных авторских TS/TSX-модулях.
  Имена фабрик не регистрируются в ядре; один файл не обязан соответствовать одному прибору.
- [x] Использовать одно правило AST-полей для обнаружения, инспектора и DSL-предложений:
  явный override после spread редактируем; перекрытое/неоднозначное поле — нет.
- [x] Не править общее тело функции/метода вместо экземпляра; не вставлять скрытые
  overrides для shorthand/accessor/computed свойств.
- [x] Сохранять явную identity сигналов, распознавать реальные core `bind()`/`signal()`
  через aliases/namespaces, не принимать произвольный `.bind` за контракт DSL.
- [x] Локальный source/CAS regression: 16 новых + 3 прежних теста, **19 pass / 0 fail**
  на Node 22.16.0 / TypeScript 5.8.3 с адаптацией тестового runner; исходный код падает
  на 14 новых проверках. Strict typecheck AST-модуля и diff-check также пройдены.
- [ ] Штатные Bun/TypeScript 7/6/architecture и полная регрессия на новом SHA.
  Локальный Node-прогон не заменяет эту приёмку.
- [ ] Реальный Shell: две независимые проектные фабрики в одном файле и в нескольких
  модулях → выбор → свойства → drag/undo → сохранение → повторное открытие.
  Проверить computed/ambiguous состояния, source mapping и отсутствие publish/apply.
- [ ] Затем проверить новый тип через build, HMI, сигналы, отчёт и runtime без
  доменных специальных условий. Полная расширяемость Shell этим инкрементом не закрыта.

**Критерий:** для нового понятия достаточно исходника проекта и существующих контрактов.
Если требуются специальные условия в независимых слоях, сначала исправляется общий
контракт на реальном сценарии; обязательные registry/manifest/ontology не добавляются.
